# 家长端 App 功能清单 v1

> 面向设计交付。每项功能都标注了**数据来源**（追溯到已实现的传感器）和**优先级**。
> P0 = demo 必须有；P1 = 完整产品必须有；P2 = 加分项。

---

## 零、设计原则（先读这段，它决定了下面所有功能的形态）

1. **不做实时监视。** 同样的数据可以做成"护眼助手"或"监控孩子的工具"。
   - ❌ 不要：秒级在座直播、"孩子离开了桌子"即时推送、"今天偷懒 23 分钟"
   - ✅ 要：每日聚合洞察、趋势对比、"今天有 3 段 20 分钟以上的深度专注"
2. **孩子有知情权。** 设备端有可见的记录指示；App 内有"孩子端可见内容"开关。孩子应该能看到自己的数据。
3. **正向措辞。** 所有文案描述行为不评价人。"距离偏近 12 次"而不是"坐姿差"。
4. **不谎报精度。** 光照传感器未标定且接近饱和，**只能显示相对百分比和分级，不能显示 lux 数值**。
5. **数据可导出、可删除。** 儿童数据属敏感个人信息，需单独告知与同意。

## 一、首页 · 此刻 `P0`

| 元素 | 数据来源 | 说明 |
|---|---|---|
| 在座状态 + 已持续时长 | PIR + VL53L0X 融合 → `PRESENT`/`AWAY` | 显示状态，**不推送状态变化** |
| 今日学习时长 / 目标进度环 | `daily_study_seconds` / 每日目标 | 默认目标 4h |
| 本次连续学习 | `study_seconds` | |
| 环境三色灯：光照 / 距离 / 温湿度 | 光敏、ToF、DHT11 | 绿=正常 黄=注意 红=异常 |
| 桌宠镜像：形态 / HP / GROW | 设备端桌宠状态 | **和孩子看到的是同一只**，见第七节 |
| 设备在线 + 最后同步时间 | Wi-Fi 心跳 | 离线要明确显示，不能假装有数据 |

---

## 二、今日报告 `P0`

- **学习时间轴**：一条横向分段条，标出在座 / 离开 / 异常段落
- **专注段落统计**：最长连续时长、平均段长、被打断次数
- **今日护眼评分** + 扣分明细（哪几项扣了多少）
- **距离**：过近次数、累计过近时长、距离分布
- **光照**：不足次数、累计不足时长、左右差值异常次数（判断是否背光/只开台灯）
- **环境**：温湿度落在舒适区间的时间占比

数据来源：全部来自设备已实现的判定逻辑，无新增硬件需求。

---

## 三、提醒与响应 `P0`

- 设备本地触发过的提醒记录：台灯太暗 / 休息喝水 / 距离过近
- 每条提醒的**响应结果**：提醒后 N 分钟内该项指标是否改善

> **提醒响应率**是这个 App 里最有价值的独有指标。它回答的是"提醒到底管不管用"，
> 而不只是"提醒了几次"。做趋势后还能看出孩子对哪类提醒开始脱敏。

---

## 四、趋势与洞察 `P1`

- **周报 / 月报**：学习时长趋势、护眼评分趋势、问题类型 Top 3、本周 vs 上周
- **AI 自然语言总结**（Agent Stack 出场点）：把一周数据写成家长能读的一段话
- **习惯洞察**：
  - 一天中效率最高的时段
  - 平均专注时长的变化曲线
  - **作息基线**：系统学会这个孩子自己的正常模式，异常是相对于他自己判定的，
    不是相对于教科书。这是长期记忆(mem9)的用武之地。

---

## 五、目标与规则 `P1`

- 每日学习目标（默认 4h）
- 学习时段安排（周一至周日分别设置）
- 番茄钟参数：专注时长 / 休息时长
- 阈值调整：推荐距离范围（默认 400–850mm）、光照下限、提醒冷却（默认 30min）
- 提醒方式开关：设备语音 / 设备动画 / App 推送 / 组合

---

## 六、设备管理 `P1`

- Wi-Fi 配网
- 固件版本 / OTA
- **传感器校准**：光照要做两点校准才能报绝对照度。没校准就只显示百分比。
  这一项直接决定第 0 节第 4 条能不能放开。
- 多设备 / 多孩子切换

---

## 七、桌宠共育 `P2` ← 建议重点做，这是翻转"监控感"的关键

- 家长和孩子**看到同一只桌宠**，共享 HP 和 GROW
- 家长可以给桌宠喂食 / 奖励（消耗家长设定的奖励点）
- 成长里程碑通知（进化、达成连续目标）
- 家长的行为也影响桌宠 → 从"我在看着你"变成"我们一起养它"

> 这一节是产品叙事的支点。技术上不难（数据已经有了），但它把亲子关系
> 从监督翻转成合作，是创新分和向善分的主要来源。

---

## 八、对话 `P1`

基于 Agent Stack 的自然语言问答，家长可以直接问：
- "今天孩子为什么效率低？"
- "这周比上周有什么改善？"
- "台灯该怎么调？"

回答要基于长期记忆中的个人基线，而不是通用建议。

---

## 九、通知策略 `P1`

- 每日总结推送（晚上固定时间，非实时）
- 周报推送
- 真正的实时告警**只保留一类**：连续 N 分钟距离严重过近
- 免打扰时段

> 通知设计是"助手 vs 监控"的分水岭。默认只给聚合推送，实时告警要用户主动开启。

---

## 十、当前硬件做不到的（写清楚，避免设计出画饼界面）

| 做不到 | 原因 |
|---|---|
| 坐姿图像、身份识别 | **没有摄像头** |
| 识别是谁在座、数人数 | PIR 只输出移动/静止一个位 |
| 显示绝对照度（lux） | 光敏未标定且接近饱和，只有相对量 |
| 严格的"眼睛到书本距离" | ToF 测的是最近物体距离，是倾身程度的代理指标 |
| 精确温湿度 | DHT11 精度 ±2°C / ±5%RH，只够做舒适度分级 |
| 环境噪音 / 被打扰检测 | 麦克风尚未接入 |

---

## 十一、给设计的优先级建议

**demo 三分钟里真正会被看到的**：首页此刻 → 今日报告 → 桌宠共育 → AI 周报总结。
这四屏做透，比十二个模块都做一半有效。

其余按 P1 / P2 排期。
